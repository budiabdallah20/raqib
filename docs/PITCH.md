# 🎤 PITCH — رقيب RAQiB (10 شرائح)

## 1. المشكلة
دقائق ثمينة من كل محاضرة تُهدر في نداء الأسماء أو مراجعة كشول ورقية. والأبد سلبي أكبر: **طلاب يتغيبون بصمت** حتى مادة الامتحان، وتراكم غياب لا يُكتشف إلا متأخرًا.

## 2. الحل
منصة **رقيب**: الدكتور يفتح المحاضرة بسقسرة (QR يدور كل 20 ثانية)، الطالب يمسح من متصفحه في 3 ثوانٍ، والحضور يُسجل فوريًا مع سياسة حرمان محسوبة تلقائيًا.

## 3. كيف يعمل
1. الدكتور يفتح المحاضرة ← لوحة عرض كبيرة برمز متجدد + كود يدوي 6 أرقام.
2. الطالب يمسح ← تأكيد فوري «حاضر / متأخر».
3. التقرير يتحدث لوحده ← CSV/PDF بهوية الكلية.

## 4. الأثر
- **840 ورقة حضور يدويًا ← صفر** لكل مادة في الترم.
- حالة كل طالب (آمن/مخاطرة/محروم) محسوبة لحظيًا — تدخل مبكر بدل مفاجأة الحرمان.
- تقارير جاهزة للطباعة بهوية كلية العلوم خلال ثوانٍ.

## 5. صدق البيانات
كل رقم في المنصة (واجهة الهبوط، اللوحات، التقارير) محسوب مباشرة من قاعدة البيانات (`GET /api/public/metrics`) — وعند توفر بيانات تجريبية تظهر علامة **Demo Mode** صراحة.

## 6. الأمان
- JWT httpOnly + bcrypt(12) + HTTPS.
- رمز QR يعيد توليده كل 20 ثانية (صلاحية قصيرة) — منع نسخ/تداول الرمز.
- مسح واحد لكل طالب في كل محاضرة — مسح مكرر مرفوض بوضوح.
- AuditLog لكل مسحة/تصدير/تعديل درجة مع IP + الجهاز + التوقيت.
- الطالب لا يرى رمز المحاضرة أبدًا (select صريح) — مختبَر آليًا في Tests.

## 7. ما الذي يجعله عمليًا اليوم
- يعمل على الجهاز محليًا (HTTPS:5000) ببيانات ديمو كاملة: 180 طالبًا / 12 مادة / 22K مسحة.
- جاهز للنشر: Docker + PostgreSQL + نسخ احتياطي يومي + `/api/health`.

## 8. الخطة (3 أشهر)
| الشهر | الهدف |
|---|---|
| 1 | تجربة هادئة في مادة واحدة + تجهيز دومين وشهادة مؤسسية |
| 2 | التوسع لقسم كامل + تقارير شهروكة رسمية + Web Push |
| 3 | اعتماد إداري + تكامل مع نظام شؤون الطلاب |

## 9. الفريق
قسم الرياضيات وعلوم الحاسب — كلية العلوم، جامعة السويس. فريق صغير بمهندس واجهة + مطور خلفية + مدرس مشرف.

## 10. الشعب النهائي
«رقيب — الحضور صار أذكى. والوقت صار لك.»
جاهز لإخراج من المحاضرة الأولى غدًا.
