# 🎬 سيناريو العرض — رقيب أمام لجنة العميد (7 دقائق بالضبط)

> **تجهيز مسبق (يوم العرض):**
> 1. `npm run seed:demo` (يجهّز 180 طالبًا و22 ألف مسحة) ← ثم `npm run dev:https` ← افتح `https://localhost:5000`.
> 2. جهّز 3 تبويبات: **(1)** واجهة الهبوط **(2)** جاهز لتسجيل دخول `student@raqib.edu / Student@123` **(3)** جاهز لتسجيل `professor@raqib.edu / Prof@123`.
> 3. الهاتف جنبك بكاميرا جاهزة لمسح QR من شاشة الدكتور.

## 3 عقبات متوقعة أثناء العرض (وخطتها جاهزة)
- **الطالب مسح رمزًا قديمًا؟** التدوير كل 20 ثانية يقتل الرمز القديم فورًا — الرسالة «صلاحيته انتهت» تظهر في ثوانٍ: هذه **نقطة بيع للأمان**، وليست عيبًا — أشر لها بفخر.
- **الشبكة بطيئة؟** الكود اليدوي 6 أرقام يعمل بلا WiFi ولا كاميرا — أدخله يدويًا أمام اللجنة.
- **تائق أي شيء غريب؟** زر «إعادة ضبط بيانات العرض» يعيد كل شيء نظيفًا في ~15 ثانية (الديمو idempotent).

## ملاحظة الأرقام
كل رقم معروض إما محسوب فعليًا من قاعدة البيانات عبر `GET /api/public/metrics`، أو موسوم بوضوح بـ«بيانات تجريبية» — التزام صريح أمام اللجنة.
